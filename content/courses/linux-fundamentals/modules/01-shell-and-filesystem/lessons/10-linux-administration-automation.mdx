6. Project 3 — Build a Backup Automation Script
Now we will create a backup utility.

This combines:
- Variables.
- Directory checks.
- Date and time.
- File copying.
- Conditions.
- Logging.
- Exit statuses.
Step 1 — Create the backup script
nano bin/backup.sh


Add:
#!/usr/bin/env bash

SOURCE_DIR="$PROJECT_DIR/data/application"
BACKUP_DIR="$PROJECT_DIR/data/backups"
LOG_FILE="$PROJECT_DIR/logs/backup.log"

TIMESTAMP="$(date +%Y-%m-%d_%H-%M-%S)"
DESTINATION="$BACKUP_DIR/backup-$TIMESTAMP"

echo "Starting backup..."

if [[ ! -d "$SOURCE_DIR" ]]; then
    echo "ERROR: Source directory does not exist."
    exit 1
fi

mkdir -p "$BACKUP_DIR"

if cp -a "$SOURCE_DIR" "$DESTINATION"; then
    echo "SUCCESS: Backup completed."
    echo "Backup location: $DESTINATION"

    echo "[$TIMESTAMP] Backup completed: $DESTINATION" >> "$LOG_FILE"
else
    echo "ERROR: Backup failed."
    echo "[$TIMESTAMP] Backup failed." >> "$LOG_FILE"
    exit 1
fi

echo "Backup operation finished."


Step 2 — Make executable
chmod +x bin/backup.sh


Step 3 — Run it
Make sure PROJECT_DIR is set in your current shell:
./bin/backup.sh


Expected:
Starting backup...
SUCCESS: Backup completed.
Backup location: .../data/backups/backup-...
Backup operation finished.


Step 4 — Inspect backups
find data/backups -maxdepth 3 -type f


Step 5 — Inspect backup logs
cat logs/backup.log


Step 6 — Run it a second time
./bin/backup.sh


It should create another timestamped backup.
Important limitation
This script currently relies on the exported PROJECT_DIR variable in your current shell.

If you open a new terminal, the variable may not be available.

We will fix this in the main administration script by calculating paths relative to the script's own location.

Also, this teaching backup is not a database-consistent backup. A live production database needs database-specific backup procedures.

8. Project 5 — Create a Main Administration Command
Now we will build the central entry point for the toolkit.

The administrator will be able to run:
./bin/admin.sh info
./bin/admin.sh backup
./bin/admin.sh logs
./bin/admin.sh config


This is similar to a small command-line application.
Step 1 — Create the script
nano bin/admin.sh


Add:
#!/usr/bin/env bash

set -u

# Resolve the project directory from this script's location.
SCRIPT_DIR="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)"
PROJECT_DIR="$(cd -- "$SCRIPT_DIR/.." && pwd)"

LOG_DIR="$PROJECT_DIR/logs"
REPORT_DIR="$PROJECT_DIR/reports"

mkdir -p "$LOG_DIR" "$REPORT_DIR"

log() {
    printf '[%s] %s\n' "$(date '+%Y-%m-%d %H:%M:%S')" "$1"
}

show_usage() {
    cat <<EOF
Linux Administration Toolkit

Usage:
    admin.sh COMMAND

Commands:
    info       Display system information
    backup     Back up application data
    logs       Display application errors
    config     Display application configuration
    help       Display this help
EOF
}

show_info() {
    "$SCRIPT_DIR/system-info.sh"
}

run_backup() {
    PROJECT_DIR="$PROJECT_DIR" "$SCRIPT_DIR/backup.sh"
}

show_logs() {
    local FILE="$LOG_DIR/application.log"

    if [[ ! -f "$FILE" ]]; then
        echo "Application log does not exist."
        return 1
    fi

    echo "Application errors:"
    grep 'ERROR' "$FILE" || true
}

show_config() {
    local FILE="$PROJECT_DIR/config/app.conf"

    if [[ ! -f "$FILE" ]]; then
        echo "Configuration file missing."
        return 1
    fi

    cat "$FILE"
}

COMMAND="${1:-help}"

case "$COMMAND" in
    info)
        log "Collecting system information."
        show_info
        ;;
    backup)
        log "Starting backup."
        run_backup
        ;;
    logs)
        log "Inspecting application logs."
        show_logs
        ;;
    config)
        log "Displaying configuration."
        show_config
        ;;
    help|-h|--help)
        show_usage
        ;;
    *)
        echo "Unknown command: $COMMAND" >&2
        show_usage >&2
        exit 2
        ;;
esac


Step 2 — Make executable
chmod +x bin/admin.sh


Step 3 — Test help
./bin/admin.sh help


Step 4 — Display system information
./bin/admin.sh info


Step 5 — Run a backup
./bin/admin.sh backup


Notice that this time the backup works even if PROJECT_DIR was not exported in your terminal.

Why?

The main script calculates its own location and passes the correct project directory to the backup script.
Step 6 — Inspect logs

Step 7 — Display configuration

Step 8 — Test an invalid command

Check:

9. Understand the Main Script Architecture
We used several important Bash techniques.
9.1 BASH_SOURCE
"${BASH_SOURCE[0]}"


This refers to the currently executing Bash source file.

It helps scripts locate themselves independently of the current working directory.
9.2 dirname
dirname -- "${BASH_SOURCE[0]}"


Extracts the directory portion of the script path.
9.3 cd
cd -- "$SCRIPT_DIR/.."


Moves to the parent directory of bin.
9.4 Command substitution
PROJECT_DIR="$(cd -- "$SCRIPT_DIR/.." && pwd)"


Executes commands and captures their output.
9.5 local
local FILE="$LOG_DIR/application.log"


Creates a function-local variable.
9.6 case
case "$COMMAND" in
    info)
        show_info
        ;;
    backup)
        run_backup
        ;;
esac


This is useful when implementing command-line interfaces with multiple operations.
9.7 Why grep ... || true?
grep 'ERROR' "$FILE" || true


grep returns:
- 0 when a match is found.
- 1 when no match is found.
- A value greater than 1 for an actual error.
In this report command, no matching error is an acceptable result. || true prevents that normal no-match condition from being treated as a command failure.

This is an intentional use of Bash's command-status behavior, not a universal solution for error handling.

11. Project 7 — Generate a Complete Administration Report
Now we will combine system information, configuration and log analysis into one final report.

Create:
nano bin/full-report.sh


Add:
#!/usr/bin/env bash

set -u

SCRIPT_DIR="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)"
PROJECT_DIR="$(cd -- "$SCRIPT_DIR/.." && pwd)"

REPORT_DIR="$PROJECT_DIR/reports"
REPORT_FILE="$REPORT_DIR/full-report.txt"
APP_LOG="$PROJECT_DIR/logs/application.log"
CONFIG_FILE="$PROJECT_DIR/config/app.conf"

mkdir -p "$REPORT_DIR"

{
    echo "===================================="
    echo "     LINUX ADMINISTRATION REPORT"
    echo "===================================="

    echo
    echo "GENERATED AT"
    date

    echo
    echo "SYSTEM"
    hostname
    uname -r
    grep '^PRETTY_NAME=' /etc/os-release

    echo
    echo "DISK"
    df -h /

    echo
    echo "MEMORY"
    free -h

    echo
    echo "APPLICATION CONFIGURATION"

    if [[ -f "$CONFIG_FILE" ]]; then
        cat "$CONFIG_FILE"
    else
        echo "Configuration not found."
    fi

    echo
    echo "APPLICATION ERROR COUNT"

    if [[ -f "$APP_LOG" ]]; then
        grep -c 'ERROR' "$APP_LOG" || true
    else
        echo "Application log not found."
    fi

    echo
    echo "REPORT FINISHED"

} > "$REPORT_FILE"

echo "Report created: $REPORT_FILE"


Make executable:
chmod +x bin/full-report.sh


Run:
./bin/full-report.sh


Inspect:
cat reports/full-report.txt


You now have a report that combines information from multiple Linux subsystems.

18. Important Preparation for Module 02
Before studying permissions, understand this mental model:
Linux file
    |
    +-- Owner
    |
    +-- Group
    |
    +-- Permissions
           |
           +-- Read
           +-- Write
           +-- Execute


Linux does not simply ask whether you are an administrator or a normal user. It evaluates ownership, groups, permissions and additional access-control mechanisms.

This is one of the most important foundations for understanding Linux security and production server administration.
