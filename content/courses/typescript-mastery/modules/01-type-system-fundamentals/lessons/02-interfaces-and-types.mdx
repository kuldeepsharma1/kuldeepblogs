# Interfaces and Type Aliases

Both `interface` and `type` let you define the shape of data. Knowing when to use each is key to clean TypeScript code.

## Interfaces

```typescript
interface User {
  id: string;
  name: string;
  email: string;
  role: "admin" | "user";
}

// Extend interfaces
interface AdminUser extends User {
  permissions: string[];
}
```

## Type Aliases

```typescript
type Status = "active" | "inactive" | "pending";

type ApiResponse<T> = {
  data: T;
  error: string | null;
  status: number;
};
```

## When to Use Which

| Feature | Interface | Type Alias |
|---------|-----------|------------|
| Object shapes | ✅ | ✅ |
| Union types | ❌ | ✅ |
| Intersection | extends | `&` |
| Declaration merging | ✅ | ❌ |
| Computed properties | ❌ | ✅ |

<Callout type="tip">
  Rule of thumb: Use `interface` for public API contracts and object shapes. Use `type` for unions, intersections, and computed types.
</Callout>

## Key Takeaways

- Interfaces are best for object shapes and extendability
- Type aliases handle unions, tuples, and complex types
- Interfaces support declaration merging
- Both are equally valid in most cases
